Lesson 0002 · Planning

Imagine with the real env

If CEM cannot swing up Pendulum while it is allowed to cheat with env.step, later latent plots are not a world-model bug. They are a planner bug.

Mission hook: later you will abort when imagination disagrees with reality. Today imagination is reality, copied and rewound. The only thing that can fail is the search over action sequences.

A model, then a plan

Sutton & Barto, chapter 8 call anything that predicts the next state and reward a model, and call planning any computation that turns a model into a way of acting. You already have a perfect sample model: env.step. Phase 2 will replace that call with a network. The planner should not have to change.

The planner does not learn a policy network. At each real timestep it searches for a short sequence of actions, sends the first one, and searches again. That loop is receding-horizon model-predictive control: plan many steps, commit one.

imagine a0 a1 a2 a3 a4 a5
commit a0 replan replan replan replan replan

Open-loop would fire a0…a5 without looking again. Receding horizon is how the parking assistant will steer: a new plan after every real observation, later with a distrust gate on that same imagined suffix.

CEM in five lines

The search is the cross-entropy method on action sequences, not on network weights. Pinneri et al. 2020, Appendix A is the vanilla CEM-MPC loop we implement. Ignore iCEM (colored noise, elite memory) until this version works.

  1. Sample N sequences of length H from a Gaussian over actions.
  2. Clip to the action box. Score each by rolling the model.
  3. Keep the K cheapest sequences (the elites).
  4. Refit mean and std to those elites. Repeat a few times.
  5. Execute the first action of the best sequence. Shift the mean. Replan.

“Best sequence,” not “the mean”: the mean was never rolled out. Pinneri §3.3 notes that distinction. We take the elite that actually got the low cost.

Pendulum-v1, then rewind

Pendulum-v1 is the warmup in PLAN.md: one torque in [-2, 2], observation [cos θ, sin θ, θ̇], upright at θ = 0, 200-step truncation. Reward is already a cost with a minus: −(θ² + 0.1 θ̇² + 0.001 τ²). CEM minimizes the sum of −reward over the horizon.

Wrapper trap. gym.make("Pendulum-v1") wraps the physics in TimeLimit(200). Planning must call env.unwrapped.step after copying env.unwrapped.state. If you plan with the wrapped env.step, imagined rollouts spend the real episode’s 200 steps and the pendulum “dies” while you are only thinking. After each candidate, put the state back. Never reset to score a plan: reset randomizes θ.

The Phase 1 Pendulum pass is a plot, not a feeling. From the repo root:

source .venv/Scripts/activate
python scripts/cem.py

First command is a 1-D self-check. Second runs random, then CEM, and writes artifacts/pendulum_cem.png (gitignored). You want CEM return much better than random, and |θ| near 0 in the last 50 steps.

Parking is the same optimizer with a different cost and a harder clone. Do not start that until this pendulum plot exists.
