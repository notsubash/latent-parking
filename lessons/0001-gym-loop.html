Lesson 0001 · Gym loop

One timestep in parking-v0

You cannot train a world model, run CEM, or distrust a rollout until you can name every field in a single transition. This lesson is that naming.

Mission hook: later you will imagine a few seconds ahead and abort when imagination disagrees with reality. The unit of imagination is the same unit you save today: (obs, action, next_obs).

The loop

Reinforcement learning’s two characters are the agent and the environment. At every step the agent sees an observation, picks an action, and the environment returns a new observation plus a reward. Spinning Up, Part 1 calls a sequence of those exchanges a trajectory.

Gymnasium is the API for that loop. Basic Usage is four calls: make, reset, step, close. You already ran scripts/sanity_check.py. Here is the same loop with the names we will keep: 

obs, info = env.reset(seed=0)
action = env.action_space.sample()
next_obs, reward, terminated, truncated, info = env.step(action)
# save (obs, action, next_obs, reward, terminated, truncated)
if terminated or truncated:
    obs, info = env.reset()
else:
    obs = next_obs

Always reset before the first step. After terminated or truncated, step is undefined until you reset again (Env.step).

What parking-v0 actually returns

Default observation type is KinematicsGoal (parking docs). reset and step give a dict with three arrays of length 6:

KeyMeaning
observation Ego vehicle: x, y, vx, vy, cos_h, sin_h, each divided by a scale.
achieved_goal The same six numbers. Reward compares this to the desired goal.
desired_goal The parking spot as the same six features (spot velocity is zero).

That dict shape is the GoalEnv contract reproduced in parking_env.py: the agent is told both “where I am” and “where I should be.”

Scale trap. Config says normalize: False, but KinematicsGoalObservation.observe() still does values / scales with scales = [100, 100, 5, 5, 1, 1]. If the array’s first entry is 0.20, the car is at x = 20 meters, not 0.20. Heading is stored as a unit vector (cos_h, sin_h), not an angle, so the planner can interpolate heading without wrapping 0/2π. Source: observation.py.

Decode one number

Actions

Action space is Box(-1, 1, (2,), float32). Those bounds are normalized commands, not meters. highway-env maps them after clipping (Actions, ContinuousAction.get_action):

IndexCommandMapped range
action[0]acceleration (throttle)[-5, 5] m/s²
action[1]steering[-π/4, π/4] rad (±45°)

Order trap. It is [acceleration, steering], not the reverse. If you later plug CEM into the wrong index, the car will look “steerable” while you are actually flooring the throttle. Believe the source, not a comment.

When an episode ends

Gymnasium split the old done flag on purpose (step API, v0.26):

FlagIn this env
terminated Crash into a wall (or later, a parked car), or success: weighted distance to the spot is small enough.
truncated Simulated time hits duration = 100 seconds.

Each step advances time by 1 / policy_frequency. Default policy_frequency is 5 Hz, so one action lasts 0.2 s, and a full timeout is 100 × 5 = 500 actions (AbstractEnv.step). Physics still runs at 15 Hz: three internal bicycle-model steps per action you send.

Random actions usually hit a wall long before 500 steps. That is expected. You still save those transitions: a world model must see crashes too, or Phase 6’s distrust signal will be fiction.

Do this now

The Phase 0 pass is a dataset on disk, not a feeling of understanding. From the repo root:

source .venv/Scripts/activate
python scripts/collect_random.py

That script is the loop above, written to data/random_parking.npz (gitignored). After it prints counts, you should be able to say out loud: observation keys, action bounds and order, and max episode length.
