Parks, not only crashes

Phase 2 trains f(s, a) → s′ on kinematics. If the dataset never contains a park, the network cannot imagine one, and CEM will query states f has never seen.

Mission hook: later you abort when imagination disagrees with reality. That only works if imagination was trained on the kind of driving the planner actually does, including slow, headed, successful parks.

What is predicted

Nagabandi et al., 2018 write the learned model as ŝt+1 = st + f̂(st, at): next kinematics, not the scalar reward, not pixels. PLAN.md is the same contract without the delta trick: f(s, a) → s′, MSE on the six-vector x, y, vx, vy, cos_h, sin_h.

Planning then reuses lesson 0002: CEM rolls f for a short horizon and executes the first action. TD-MPC2 does that in a latent z and adds value heads. Skip those heads. Ask only: what is predicted, and how is a plan scored.

The identity bar

Phase 2 pass #1: one-step prediction must beat predict no change, s′ = s, which ignores the action. That is a real baseline, not a joke. On a 0.2 s step the car barely moves, so identity MSE looks small until you look at vx, vy.

Your data/random_parking.npz (8000 steps, 91 finished episodes) has zero successes. Every completed episode crashed. Identity on that file is overall MSE ≈ 0.0033 in stored coordinates (x is meters/100). A later MLP must beat that number in the same space.

Distribution trap. Nagabandi §IV-D mix random data with on-policy MPC rollouts because the planner visits a different (s, a) distribution than noise. Random parking never reverses into a stall with the right heading. Train only on crashes, and CEM’s first “good” plan is out of distribution.

Error grows with horizon

Nagabandi eq. (3) is the plot PLAN.md asks for next: feed f’s own prediction back in, compare to the true trajectory at H = 1, 2, 5, 10, 20. A 15% dynamics error is almost invisible at H = 1 and obvious at H = 8. Identity is wrong immediately if anything moved.
