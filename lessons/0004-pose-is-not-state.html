Lesson 0004 · Hidden velocity

Pose is not the state

A parking stall is a pose. The bicycle that gets there is a pose plus a speed. Drop vx, vy and the same MLP is guessing which of two cars it is watching.

Mission hook: later you abort when imagined rollouts disagree. Disagreement is interesting only after you have seen imagination fail for a reason you can name. Today that reason is missing velocity.

State vs observation

Spinning Up calls a state a complete description of the world, and an observation a partial one. When the agent sees the full state, the environment is fully observed. When it does not, it is partially observed. Transitions in an MDP depend on the latest state and action only (the Markov property; same page, “Formalism”).

Default parking-v0 kinematics x, y, vx, vy, cos_h, sin_h are enough for the bicycle: Vehicle.step does position += velocity * dt, then updates heading and speed from steering and throttle. Hide vx, vy and two egos that share a pose are the same observation. Same action, different next x. That is no longer Markov in the features you kept.

Two cars, one pose

Throttle and steering are zero. Only the hidden speed differs. Click.

A cheap patch, not the product

Stack the last two poses. The delta over dt = 0.2 s is a velocity estimate in meters, but stored x is meters/100, so consecutive poses differ by about 0.01 while heading is order 1. An MLP can ignore that history. Hausknecht & Stone, DRQN treat DQN’s frame stack as a finite history, then replace it with a recurrent net. We stack. No GRU yet. Expect the stack curve to sit near pose-only, not near full. That failure is the point: a hand-built memory of four numbers is not a latent you can distrust.

Do not trust overall MSE. Identity error is mostly vx, vy. A pose-only head never predicts those, so its raw loss can look smaller while open-loop pose error is worse. Compare (x, y, cos_h, sin_h) vs horizon.

Do this now

One script trains three heads on the mixed npz: full six-vector, pose-only, pose stacked twice. CEM episodes stay in train (too few to hold out). The curves are scored on held-out random episodes. 

source .venv/Scripts/activate
python scripts/train_dynamics.py

You want full one-step pose MSE below identity, pose open-loop error above full by horizon 10, and stack near pose rather than full (the history is there; the scale hides it). Plot: artifacts/pose_vs_full_horizon.png. The CEM overlay is one park sitting in 8000 random steps, so even full can look drunk there. Trust the horizon plot.
